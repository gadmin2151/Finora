# 27G Finora · Personal Finance для Android

Нативное приложение на Kotlin / Jetpack Compose для Android 8.0 и новее. Основной сценарий — быстро добавить чек в выбранную организацию. Сервер по умолчанию: `https://finora.gadmin.work`; на экране входа можно указать другой сервер Finora с действительным HTTPS-сертификатом.

**[Скачать подписанный APK 1.8.1](https://finora.gadmin.work/assets/mobile/finora-1.8.1.apk)** · [SHA-256](https://finora.gadmin.work/assets/mobile/finora-1.8.1.apk.sha256) · [Отчёт о проверке](VERIFICATION.md).

## Финансы · 1.7

В нижнем меню: **Обзор · Финансы · Добавить чек · Чеки · Помощник**. Добавление чека выделено большой центральной кнопкой. С версии 1.7.1 панель компактнее: меньше вертикальных отступов, область системных жестов находится под панелью. В 1.7.2 иконка и подпись каждого пункта центрируются по вертикали как единый блок, с равными отступами сверху и снизу. Профиль открывается по аватарке сверху.

В **Финансы → Доходы** можно вносить и исправлять разовые доходы, создавать и редактировать регулярные источники, приостанавливать их, пропускать ожидаемые поступления и отмечать получение. Доступны история, отмена зачисления и привязка уже внесённого дохода без повторного увеличения баланса. В **Долги** — выданные и полученные долги, старые обязательства без изменения баланса, частичные/полные возвраты, поиск и закрытые записи. Изменения доступны администраторам организации; участникам — просмотр.

[Инструкция и правила учёта](../docs/MOBILE-FINANCE.md).

## Съёмка чека · 1.8.1

**Добавить → Снять чек** работает как вертикальная панорама. Поместите всю ширину белой бумаги в рамку, нажмите «Начать» и медленно ведите телефон сверху вниз. Примерно каждые 0,3 секунды приложение получает новый кадр и сразу добавляет подходящий участок в длинное изображение. На экране видны счётчик кадров, добавленные участки и растущая миниатюра. «Готово» завершает уже собранный снимок.

В 1.8 захват и склейка выполняются в отдельных потоках. Алгоритм учитывает небольшие повороты, изменения расстояния и перспективы; маска белой бумаги исключает фон из сопоставления и снимка. Сохраняются мягкие градации серого, чтобы не обрезать бледный текст. Склейка работает на телефоне без сети и AI. Если итоговые кадры не совместились, просмотр показывает предупреждение: проверьте низ чека перед отправкой.

Для короткого чека достаточно одного принятого кадра. Перед добавлением в черновик доступны прокрутка и увеличение; распознавание и подтверждение расхода остаются отдельными действиями.

[Подробная инструкция и ограничения](../docs/LONG-RECEIPTS.md). Сначала обновите сервер: он сохраняет длинные изображения без прежнего уменьшения до 6000 пикселей.

## Версия 1.5.0

Новая вкладка AI: свободные вопросы, быстрые отчёты, история, уточняющие вопросы, поиск товаров и переход к исходному чеку. Поле ввода учитывает клавиатуру; черновик сообщения сохраняется при обновлении и загрузке ответа. Сводка, категории и сравнение ваших цен доступны без AI-провайдера.

Сохранены оформление с выбранным кошельком-оригами, загрузка нескольких фото, редактирование чека, профиль и обновление жестом сверху вниз. Изменений схемы локальных черновиков нет. Версия сервера 1.5 нужна для новых отчётов и AI-чата; существующий вход и чеки совместимы.

## Установка и первый вход

1. Скачайте подписанный `finora-1.8.1.apk` на телефон и откройте файл. Если Android запросит разрешение установки для браузера/файлового менеджера, разрешите его для этой установки.
2. Проверьте адрес сервера, введите свой существующий логин и пароль Finora.
3. Выберите организацию — даже если она пока одна. Название всегда доступно в верхней части приложения; нажатие переключает организацию.
4. Нажмите **«Сканировать QR»**, **«Снять чек»** или **«Из галереи»**. Для фото нажмите **«Распознать чек»**; QR открывает страницу чека через интернет телефона. Дождитесь загрузки и нажмите «Распознать этот чек». Сверьте магазин, дату, все позиции и итог, выберите счёт и нажмите **«Всё верно · подтвердить»**. При необходимости нажмите «Исправить данные и позиции»: доступны магазин, дата, товары, количество, цена, сумма строки, категория, валюта и итог. До подтверждения расход не создаётся.

Пароль администратора и OpenAI API key в APK не включены. Для мобильного приложения не нужно заново подключать OpenAI: оно использует распознавание, настроенное на сервере организации.

## Возможности

- HTTPS-вход с сохранением зашифрованной сессии в Android Keystore; работа с несколькими организациями.
- Сканер QR электронных чеков с анализом кадра 1920×1080 (либо ближайшее поддерживаемое камерой разрешение), автоприближением, фокусировкой по касанию, фонариком и ручным зумом. Распознаватель QR включён в APK и не требует загрузки модели. Поддерживаются MEV/SIFT и другие провайдеры: телефон открывает публичную HTTPS-страницу во встроенном WebView, собирает текст и полный снимок (до четырёх частей) и отправляет их серверу. Сервер распознаёт только полученные данные, без обращения к сайту чека. Поэтому сервер можно размещать в стране, откуда MEV недоступен.
- Встроенная камера и системный выбор фотографий без доступа ко всей медиатеке.
- **До 4 фотографий одного чека**: снимайте части сверху вниз с небольшим перекрытием. Можно увеличить, удалить и переставить снимки; повторяйте «Добавить часть чека» для длинного чека.
- Нормализация ориентации, JPEG-сжатие и удаление EXIF-метаданных перед отправкой. Фотографии больше 50 МБ или 100 Мп отклоняются до декодирования; итоговый файл ограничен 15 МБ.
- Приватный черновик сохраняется между запусками отдельно для сервера, пользователя и организации. При ошибке сети можно повторить отправку. Уже зарегистрированные чеки сервер распознаёт как дубликаты.
- История чеков с поиском магазина и постраничной загрузкой, обновление статуса распознавания, товары и категории, фильтры внутри чека, просмотр исходных фото, комментарии.
- Обзор по месяцам: доходы, расходы, разница, счета, категории и доступные рекомендации сервера по экономии.
- Просмотр позиций с количеством, ценой, суммой и категорией, общий итог, выбор счёта и подтверждение прямо на телефоне. Автор подтверждает свой чек; администратор — любой чек организации. Повторное подтверждение не создаёт дубль.
- Для администратора — повторное распознавание. Исправление чеков до подтверждения доступно на телефоне. Доходы и долги доступны в нативном разделе «Финансы». Удаление чеков, бюджеты, управление участниками и AI-настройки доступны через кнопку веб-версии.

Если QR ведёт только на форму проверки без самого чека, заполните её на сайте либо вернитесь и сфотографируйте бумажный чек. Наличие QR не гарантирует, что провайдер выдаёт товары по ссылке. Например, предоставленный QR Linella при проверке 25.09.2026 открывал форму без суммы и позиций; расход из такого результата автоматически не создаётся.

Отправка выполняется пока процесс приложения работает. Если Android завершит приложение до ответа сервера, черновик останется; повторите отправку после входа. Автоматической фоновой отправки и push-уведомлений в версии 1.2 нет. После приёма файлов сервером распознавание продолжается независимо от телефона.

Чеки и статистика загружаются с сервера и не кэшируются для офлайн-просмотра. Без интернета можно подготовить черновик в ранее авторизованном аккаунте. После входа/перезапуска нужно явно выбрать организацию.

## Безопасность и API

Приложение разрешает только HTTPS с системными доверенными сертификатами. API-клиент не следует редиректам. Страницы чеков могут перенаправлять внутри отдельного WebView; локальные адреса, HTTP, file/content, доступ к файлам, камере и микрофону запрещены. Cookie Finora и ключ OpenAI в WebView не передаются; данные сайтов очищаются после закрытия страницы. Cookie ограничена точным сервером, портом и API-путём. Мутации отправляют `X-CSRF-Token` и `X-Organization-ID`; совместимый с существующим сервером заголовок `X-Finora-Client: web` используется как его first-party guard, а User-Agent — `Finora-Android/1.0`.

Пароль существует только в памяти формы входа. Cookie шифруется AES-GCM ключом Android Keystore. Черновики находятся в приватном `noBackupFilesDir`, не в общей галерее. Облачное копирование и перенос данных приложения отключены. При выходе сессия отзывается на сервере; если сервер недоступен, локальная cookie удаляется и показывается уведомление о необходимости при желании отозвать серверную сессию в веб-настройках. Черновики сохраняются для повторного входа в тот же аккаунт.

Используются существующие `/api/auth/*`, `/api/accounts`, `/api/categories`, `/api/receipts/*`, `/api/dashboard`, `/api/insights`. Multipart содержит повторяющиеся поля `files`, `account_id`, `fx_rate`, `review_required=true`, **`resolve_qr=false`** и известный `Content-Length`. Для страницы с телефона дополнительно передаются `page_url` и `page_text` (до 50 000 символов), источник — `phone_page`. Даже QR на присланной фотографии не вызывает запроса с сервера к провайдеру. В форме исправления можно выбрать счёт в валюте чека и указать курс к MDL. Подтверждение без изменений использует `POST /api/receipts/{id}/accept`; исправленный чек — `POST /api/receipts/{id}/review` с полной формой и версией. Сервер проверяет авторство/роль, организацию, валюту, сумму строк и актуальность версии. Привязка произвольного существующего расхода через `/review` запрещена. Сначала обновите сервер до версии с этим API (текущая миграция `7c9120efab34`).

## Сборка

Требуются JDK 21, Android SDK platform **37.0**, build-tools **36.0.0**. Gradle **9.7.1** закреплён wrapper-ом с SHA-256; AGP **9.3.2**. Укажите `JAVA_HOME` и `ANDROID_HOME`.

```bash
cd android
./gradlew checkKotlinFormat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
./gradlew formatKotlin  # только если форматирование нужно изменить
```

Подписанный релиз, из корня репозитория:

```bash
python3 scripts/build-android.py --init-keystore  # только первая сборка
python3 scripts/build-android.py                 # все последующие обновления
```

Скрипт создаёт отдельный ключ Finora `.secrets/finora-android.p12`, хранит пароль в `.secrets/android-signing.json`, запускает формат-проверку, unit tests, release lint, R8-сборку и проверяет подпись. Результат: `artifacts/android/finora-<version>.apk` и контрольная сумма. **Сохраните резервную копию обоих файлов подписи:** обновления Android требуют тот же ключ. Не создавайте новый ключ для каждого релиза. Перед обновлением увеличьте `versionCode` и `versionName` в `app/build.gradle.kts`.

Вместо локальных файлов можно задать `FINORA_KEYSTORE`, `FINORA_STORE_PASSWORD`, `FINORA_KEY_PASSWORD`; alias ключа — `finora`. Для использования уже установленного Gradle скрипт поддерживает `FINORA_GRADLE`.

## Проверки на Android

```bash
cd android
./gradlew :app:connectedDebugAndroidTest
```

Обычный запуск проверяет приватные черновики, Android Keystore и QR-распознавание на синтетическом MEV-коде. Сетевые и UI-проверки включаются только приватным файлом `files/acceptance-credentials.json` в sandbox **тестового** приложения: `server`, `username`, `password`. Тестовый пользователь должен состоять исключительно в временных организациях с префиксом `Android QA `. Проверка отправляет синтетический нефискальный чек, комментарий и повторный upload. Никогда не используйте учётную запись с реальными финансовыми данными.

AGP может удалить тестовое приложение и его данные после connected tests. Для локального полного acceptance установите debug APK и test APK, передайте файл через `adb shell run-as work.gadmin.finora`, затем запустите `adb shell am instrument -w work.gadmin.finora.test/androidx.test.runner.AndroidJUnitRunner`. После проверки удалите временные организации, пользователя и его серверные файлы. Скриншоты Compose-тестов находятся в приватных файлах тестового приложения; они не входят в релиз.

## CI и раздача APK

Workflow [Android APK](../.github/workflows/android.yml) проверяет формат, unit tests, lint и собирает release. Для подписи настройте GitHub Actions secrets `FINORA_KEYSTORE_BASE64` (содержимое существующего `.p12` в base64), `FINORA_STORE_PASSWORD`, `FINORA_KEY_PASSWORD`. Без этих secrets CI выпускает **unsigned** APK для проверки сборки; установить его без подписи нельзя. Локальный релизный скрипт всегда проверяет настоящую подпись.

Для загрузки с вашего сервера поместите подписанный APK и `.sha256` в `/opt/finora/downloads`, добавьте `compose.mobile.yaml` последним в `COMPOSE_FILE` и обновите только API:

```bash
docker compose config --quiet
docker compose up -d --no-deps api
```

Файлы доступны по `/assets/mobile/finora-<version>.apk` через существующий HTTPS-домен. Публикуйте только APK/контрольные суммы; ключ подписи, конфигурация, тестовые данные и фотографии в `downloads` не нужны. Права каталога 0755, APK 0644. Overlay не требует миграций БД и сохраняет существующие volumes.

## Проверка релизного сканера

Оптимизированный APK проверяется отдельно от debug: ML Kit находит компоненты через reflection, и ошибка упаковки может проявиться только после R8. `scripts/check-android-release.py` запускается локальным сборщиком и CI и проверяет сохранность трёх конструкторов регистраторов.

Для проверки установленного подписанного APK на USB-устройстве соберите тестовый APK тем же ключом (signing environment как для релиза):

```bash
cd android
./gradlew -PfinoraTestBuildType=release :app:assembleReleaseAndroidTest
adb -s SERIAL install -r -t app/build/outputs/apk/androidTest/release/app-release-androidTest.apk
adb -s SERIAL shell am instrument -w -r \
  work.gadmin.finora.test/work.gadmin.finora.ReleaseSmokeInstrumentation
```

Для проверки экранов камеры добавьте `-e camera true -e organization ORGANIZATION_NAME` перед именем runner. Нужна действующая сессия, выданное разрешение камеры и пустой текущий черновик. Проверка открывает и закрывает QR и фотокамеру. Во время smoke-проверки не направляйте камеру на настоящий код: сканер может открыть страницу. Пароли и существующие черновики тест не меняет. Успех — `registrars=PASS`, при проверке камеры также `camera=PASS`, и `INSTRUMENTATION_CODE: -1`.

Runner использует только Android SDK: обычный AndroidX runner может обращаться к классам тестовой поддержки, удалённым из оптимизированного приложения. Debug-тесты по-прежнему используют AndroidJUnitRunner. После проверки удалите только вспомогательный пакет `work.gadmin.finora.test`, приложение `work.gadmin.finora` сохраняется.

Для сквозной проверки страницы добавьте `-e receiptUrl HTTPS_RECEIPT_URL -e organization "Android QA …"`. Без дополнительных флагов тест только открывает страницу. `-e captureReceipt true` отправляет её на распознавание и проверяет, что результат остался черновиком. С `-e submitReceipt true` он загружает тестовый чек парковки 30 MDL, исправляет магазин и сумму строки, подтверждает расход. Используйте только отдельную временную организацию `Android QA ` с тестовыми данными. Скриншоты `receipt-*.png` записываются в external files установленного приложения; после проверки удалите их и временную организацию. Ключ OpenAI остаётся на сервере.
