# Server settings inventory and contract

The editable list is deliberately finite: push_enabled, push_worker_enabled, push_fcm_project_id, ai_timeout (15–600 seconds), ai_cpu_threads (1–64), max_upload_mb (1–50), and mev_browser. Explicit DB overrides win over environment/default values; null resets a public field to the inherited value. No arbitrary environment, file, command, endpoint URL or IAM editor exists.

The environment/bootstrap remains responsible for DATABASE_URL, SECRET_KEY, admin password references, cookie policy, session lifetime, APP_URL, DATA_DIR, OLLAMA_URL and GOOGLE_APPLICATION_CREDENTIALS. Infrastructure secret values and ADC paths never appear in GET. Firebase Android configuration is packaged with the APK and cannot be changed by the server editor. Existing mounts and credentials are not relocated or imported by migration.

Existing organization preferences retain AI provider/model/vision model, monthly usage budget, explicit posting policy and encrypted organization OpenAI key. A new global OpenAI key is a fallback only for organizations which already explicitly selected OpenAI and lack their own key; it never changes organization provider, preferences, financial data or posting policy. Organization key wins over the global fallback.

Secrets global_openai_key and firebase_service_account have actions keep/replace/inherit/disable. Keep (including blank input) preserves the existing state. Replace validates nonempty input and encrypts using the unchanged existing key. Inherit explicitly restores environment/ADC behavior; disable suppresses fallback. No GET, response, log, audit, validation error or export includes a secret value. Firebase replacement is service-account JSON only, max64KiB, RSA2048+, matching project ID, fixed Google token/auth/certificate/universe destinations; external account credentials and arbitrary URLs are rejected. No real credentials were read/migrated during implementation.

GET/PUT /api/system/settings use the existing server_admin dependency, live authentication and mutation CSRF; organization admin status is insufficient. PUT body is {revision, changes:{allowlisted_public_field:typed_value_or_null}, secrets:{secret_name:{action,value?}}}. Unknown input and structural errors return safe422 without echo; stale revision returns409. Mutations re-check and lock live system-admin identity, lock singleton state, compare-and-swap revision and commit all changes with an audit containing only changed field names.

GET returns schema_version1/revision/groups with field name/type/editable/secret/current/effective/default/source/apply/actions metadata and secret configured/mode only. Runtime api/worker observations describe the last consumed configuration boundary, not independent proof of provider readiness or every AI request. A fresh matching revision is applied, stale/different revision is pending, missing acknowledgement is unknown. GET/save never acknowledge themselves or probe ADC/provider readiness. No readiness-test API was introduced in this change.

read_effective(env,db) returns a RuntimeSettingsSnapshot: values dictionary of the seven public allowlist keys, revision, modes for exactly two secrets, and a secret_getter callable independent of DB-session lifetime. Getter decrypt errors are safe failures and never fall back silently. record_runtime_observation(db,service,revision,now=None) is an atomic monotonic upsert; caller owns commit and must acknowledge only after consuming configuration. Shared config remains an immutable bootstrap; integrator-owned runtime_config explicitly bridges DB to request/worker consumers. Push provider changes happen at delivery boundaries; the worker polls while off without ADC discovery.
