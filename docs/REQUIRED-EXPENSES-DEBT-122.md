# Обязательные расходы и карточка долга · Android 1.22

Сайт/API и подписанный APK **1.22.0 / code 36** опубликованы 12 октября 2026 года.

## Обязательные расходы

Оплата обязательного платежа теперь создаёт проведённый ручной чек, связанный с
тем же расходом. Он появляется в списке чеков, покупках по категории и статистике
покупок с отметкой **«Обязательный расход»**. Например, оплаченная аренда в категории
«Дом» видна и в графике расходов, и при открытии этой категории.

Сумма не списывается повторно: сохраняются прежние операция, проводки, валюта,
курс и распределение по категориям. Если платёж связан с уже существующим чеком,
его позиции и оригиналы сохраняются. Неоплаченные планы остаются планами.

Для ранее оплаченных платежей предусмотрено отдельное идемпотентное заполнение
недостающих чеков. Просмотр списков и статистики сам по себе записи не создаёт.
Историческое заполнение не отправляет уведомления о новых чеках.

API чеков и покупок получает необязательное поле `mandatory_payment` с `bill_id`,
`occurrence_id`, `due_date`; операции и строки отчётов — `is_mandatory`.
Контракт дополняется без удаления прежних полей. Время записи истории долга
`created_at` явно содержит UTC-смещение.

## Карточка долга

Откройте конкретный долг в разделе долгов. В его карточке показаны остаток и
отдельные строки создания, увеличений и погашений, похожие на позиции чека.
Каждая строка содержит сумму, дату операции, время внесения, остаток после операции
и комментарий. При увеличении или погашении можно ввести **комментарий к операции**.

Время внесения показывается по Кишинёву, как остальные даты учёта. Для записи, внесённой
задним числом, дата операции остаётся отдельной: время фактической передачи денег
ранее не сохранялось. Исходная сумма старого долга не получает выдуманную дату.
Отменённые записи видны с отметкой и не влияют на остаток. После полного погашения
карточка доступна при включённом показе закрытых долгов.

Права доступа к организациям и действиям сохранены. Зависимости и схема БД
не меняются; обновление существующих платежей затрагивает только связь с чеком
и служебную отметку обязательного расхода.

## Обновление существующих платежей

Перед заполнением сохраните проверенную резервную копию БД и документов. Выполните
команды внутри нового backend-образа с конфигурацией нужной установки:

```sh
python -m app.payment_receipts --dry-run --batch-size 100
python -m app.payment_receipts --apply --batch-size 100
```

Для одной организации добавьте `--organization-id UUID`. Обработка идёт ограниченными
пакетами, с блокировкой организации при записи. Повторный запуск не создаёт новые
чеки и не меняет их версии. Несогласованная история останавливает обработку с кодом
причины; суммы и категории автоматически не исправляются.

При отмене оплаты её автоматически созданный чек скрывается вместе с отменённым
расходом. У настоящего чека, привязанного к платежу, сохраняется обычный процесс
возврата на проверку, а отметка обязательного платежа снимается.

Основные изменения: `backend/app/payment_receipts.py`, интеграция с ledger и API;
`web/src/DebtHistory.tsx`, формы и отметки в списках; Android `DebtHistoryDialog.kt`,
`FinanceEditor.kt`, модели чеков и списки покупок. Новые тесты дат долга подключены
к web-проверкам CI.
