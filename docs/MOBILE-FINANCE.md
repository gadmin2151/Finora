# Доходы и долги в Android · 1.7

Повтор подтверждения планового дохода или платежа после обрыва связи возвращает
ту же операцию, если сумма, счёт, дата и курс не изменились. Если значения другие,
сервер сообщает конфликт: откройте связанную операцию, прежде чем менять план.
Отменённую операцию нельзя повторить старым ключом запроса; новая явная оплата
требует нового ключа. Повторные запросы не создают второй расход или доход.

Для расписания на 31-е число короткий месяц использует последний день месяца,
а следующий длинный месяц возвращается к 31-му. Пропущенный платёж не изменяет
остаток; планируемые суммы остаются отдельно от реально проведённых операций.

Откройте **Финансы** в нижнем меню. Работа выполняется в выбранной организации и синхронизируется с веб-версией по HTTPS. Аватарка сверху открывает профиль. По центру нижнего меню находится большая кнопка добавления чека.

## Доходы

- **Разовый доход**: укажите сумму, счёт, дату, источник и при необходимости примечание. История позволяет исправить несвязанное разовое зачисление или отменить его с подтверждением. Отмена меняет баланс и сохраняет серверный аудит.
- **Источник дохода**: сумма, валюта, счёт, дата начала и повторение — еженедельно, ежемесячно, ежеквартально, ежегодно или один раз. План не увеличивает остаток счёта сам по себе.
- **План → Получить**: укажите фактическую сумму и дату. Если такой доход уже внесён, найдите и выберите его для привязки; деньги повторно не зачисляются. Поиск рассматривает последние 200 поступлений выбранного месяца и счёта, затем сравнивает точные сумму, дату и валюту.
- Поступление можно пропустить и вернуть в план. Источник можно редактировать, приостановить и возобновить. Если по нему уже получены деньги, смена периодичности требует нового источника — прежние записи сохраняются.
- Сводка и история переключаются по месяцам. История загружается страницами. Сводка в MDL использует сохранённые курсы; каждая запись показывает свою валюту.

## Долги

- **Записать долг**: выберите «Я дал в долг» или «Я взял в долг», человека, сумму, валюту, дату, необязательные срок и примечание.
- **Деньги передаются сейчас** меняет баланс выбранного счёта. **Ранее существовавший долг** записывает обязательство без изменения уже учтённого остатка.
- **Записать возврат** позволяет вернуть часть или весь остаток. Счёт должен совпадать с валютой долга. Для иностранной валюты укажите курс к MDL на дату операции.
- Фильтры разделяют выданные и полученные долги; доступны поиск по имени/примечанию и показ закрытых записей. Итоги разных валют показываются отдельно.
- Выдача, получение и возврат долга не считаются обычным доходом или расходом.

## Доступ и надёжность

Администратор организации управляет записями; обычный участник видит общие данные. Сервер проверяет права независимо от доступности кнопок. Пароли и ключи AI для нового раздела не нужны.

Повторная отправка формы использует тот же ключ запроса: при потере ответа повторите с теми же данными. Сервер отклоняет несовпадающие повторы и устаревшие версии. После сохранения обновляются список, остатки и обзор. Жест сверху вниз и кнопка обновления заново запрашивают сервер.

Изменения финансов требуют связи с сервером; очереди автономных денежных операций нет. Открытая форма сохраняется при повороте экрана, но ещё не является постоянным черновиком. Для создания/архивации счетов используйте веб-версию. API и схема базы данных совместимы с сервером Finora 1.6 — новых миграций нет.
# Unfinished manual receipts

The web manual receipt form saves incomplete inputs and its request UUID in
`sessionStorage`, scoped by user and organization. Closing the form or reloading
the same tab resumes the draft; closing the tab ends that browser session.
Successful posting clears the draft. An explicit, confirmed deletion starts a
new draft next time. Browser storage failures remain visible in the form.
This draft storage does not post an expense or replace server validation.

Android keeps a separate `manual-receipt.json` AtomicFile in the existing
backup-excluded app-private workspace directory. A manual draft does not erase
the photo draft. Returning from the editor flushes it to disk; Capture offers
Continue manual receipt. The form and request UUID are saved before posting and
cleared only after acknowledgement. An unreadable draft is retained until the
user explicitly deletes it. Drafts remain local and require the same server,
user and organization to resume.
