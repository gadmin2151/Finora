# Авторы чеков и категории товаров

В карточке и истории чека показан пользователь, который его добавил. Исправление или подтверждение другим участником не меняет автора. Чеки, товары и статистика остаются общими внутри выбранной организации.

- **Чеки → Кто добавил чек** — история выбранного пользователя.
- **Покупки → Кто добавил чек** — товары этого пользователя вместе с поиском, категориями и периодом.
- **Анализ и экономия → Категории по пользователям** — распределение покупок из подтверждённых чеков за выбранный период. Валюты показаны отдельно. Возвраты учитываются в финансовых отчётах; график товаров показывает исходные покупки.
- **Android** — автор в истории и внутри чека; фильтр автора в чеках и списке товаров категории.

При подтверждении ручного или исправленного чека пустые категории определяются по правилам организации и каталогу товаров. Можно оставить «Определить автоматически при сохранении» или выбрать категорию самостоятельно. Явный выбор сохраняется; неоднозначные товары остаются без категории, чтобы не искажать аналитику. После изменения названия ранее распознанная категория сбрасывается для повторного определения, если в редакторе её не выбрали вручную.

Автор берётся из авторизованной сессии, а не из данных клиента. Для старых записей без сохранённого автора используется «Автор не указан». Удаление участника из организации не скрывает его прежние чеки от остальных участников.

## API и обслуживание

`GET /api/receipt-authors` возвращает авторов чеков текущей организации. Параметр `created_by=<user UUID>` поддерживается списками чеков, покупок и финансовыми отчётами; `created_by=unknown` выбирает старые чеки без автора. Пустой параметр означает всех. Это фильтр **автора чека**, а не плательщика или последнего редактора. В отчётах с этим фильтром учитываются связанные возвраты, но не операции без чека.

Администратор может заполнить только пропущенные категории:

```http
POST /api/categories/refresh
X-Organization-ID: <organization UUID>
X-CSRF-Token: <session CSRF token>
Content-Type: application/json

{"only_uncategorized": true, "after": ""}
```

Используйте обычную авторизованную сессию. Обрабатывается до 50 чеков за запрос; повторяйте запрос с `after`, равным `next_cursor`, пока курсор не станет `null`. Режим сохраняет заполненные категории, суммы, счета, названия и оригиналы. Распределение проведённых расходов пересчитывается для аналитики. Чеки с возвратами или несогласованными суммами пропускаются с причиной в `skipped`; неизвестные товары не получают случайную категорию. Перед обслуживанием рабочей базы сделайте резервную копию.

Поля API добавлены совместимо со старыми клиентами. Изменение схемы БД не требуется: идентификатор автора уже хранился в чеке.
